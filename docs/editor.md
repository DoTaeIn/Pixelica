# Pixelica 2D 에디터

`tools/editor/`의 독립적인 데스크톱 개발 도구입니다. 기본 게임 SDK에 편집기 의존성을
추가하지 않으며, 별도 CMake 프로젝트가 기존 2D 렌더러를 공유 라이브러리로 연결합니다.
Python/Tk가 창과 도구를 표시하고 실제 장면 픽셀은 Pixelica 2D 렌더러가 만듭니다.

## 작업 흐름

장면 목록과 캔버스에서 선택 → 드래그 배치 → 속성 수정 → 저장 → 실행 → 정지 순서입니다.
편집 데이터와 실행 데이터를 분리하므로 실행 중 이동한 위치는 저장되지 않습니다.
조작 가능한 오브젝트의 이동 속도와 자동 이동 속도를 속성에서 지정할 수 있습니다.

새 프로젝트는 외부 이미지 없이 즉시 편집·실행할 수 있는 샘플 장면으로 시작합니다.
이미지는 프로젝트 폴더 안 에셋으로 복사하며, 파일 이름이 같은 다른 이미지를 덮어쓰지 않습니다.

## 구조와 3D 확장 지점

| 파일 | 역할 |
| --- | --- |
| `tools/editor/pixelica_editor/model.py` | 프로젝트·오브젝트·컴포넌트, 검증, 저장·열기, 에셋 |
| `tools/editor/pixelica_editor/runtime.py` | 2D 렌더러 어댑터와 실행 상태 |
| `tools/editor/pixelica_editor/app.py` | 창, 선택, 속성, 배치, 실행 취소, 파일 작업 |
| `tools/editor/native/` | Pixelica C API와 Python 사이의 작은 브리지 |
| `tools/editor/launch_editor.py` | 의존성 확인, 브리지 빌드, 실행·테스트 |

오브젝트는 `id`, `name`, `kind`, `visible`, `transform`, `components`를 갖습니다.
transform의 position·rotation·scale은 모두 3개 값을 가지며 rotation은 도 단위입니다.
2D 백엔드는 위치 X/Y, 회전 Z, 크기 X/Y를 사용합니다. 사용하지 않는 축도 저장됩니다.
컴포넌트는 이름으로 구분하고, 2D 그림 속성은 `sprite2d`, 이동 속성은 `motion2d`에 둡니다.

나중에 3D를 추가할 때 프로젝트 저장·오브젝트 식별·파일 작업은 유지하고,
`mesh3d` 컴포넌트와 3D 렌더러 어댑터, 해당 뷰포트의 카메라·조작 도구를 연결합니다.
현재 3D 렌더러를 편집기에 연결한 것은 아닙니다.

## 저장과 데이터 보호

프로젝트는 `format: "pixelica.project"`, `version: 1`인 UTF-8 JSON입니다.
선택·일시정지·실행 중 위치·렌더러 포인터는 저장하지 않습니다.
저장은 같은 폴더의 임시 파일을 쓴 뒤 교체하며 실패 시 기존 프로젝트 파일을 보존합니다.
다른 이름으로 저장할 때 참조 에셋을 새 폴더로 복사하고 원래 프로젝트는 유지합니다.
잘못된 파일을 열 때 현재 편집 중인 프로젝트를 바꾸지 않습니다.

아직 적용하지 않은 속성 입력도 변경으로 취급합니다. 저장·실행·선택 변경 전에 입력을 검증하고
반영하며, 새로 만들기·열기·닫기는 저장/버리기/취소를 확인합니다. 실행 취소는 최대 50단계를
유지하고 드래그 한 번을 한 단계로 기록합니다. 다른 폴더로 저장하면 에셋의 기준 폴더가 바뀌므로
이전 실행 취소/다시 실행 기록을 초기화합니다. 같은 폴더의 다른 이름 저장은 기록을 유지합니다.

숫자의 유한성, 크기·개수 제한, 중복 ID, 포맷 버전과 에셋 경로를 검증합니다.
프로젝트에서 코드나 명령을 실행하지 않습니다. 에셋은 프로젝트 폴더 안 상대 경로만 사용합니다.
라이브러리를 직접 지정할 때 `PIXELICA_EDITOR_LIBRARY`는 신뢰하는 로컬 파일만 가리켜야 합니다.

이미지는 `assets/<내용 해시>.<확장자>`로 복사합니다. 가져오기 실패나 이미지 변경/삭제 후
사용하지 않는 파일은 자동으로 삭제하지 않습니다. 프로젝트 JSON과 assets 폴더를 함께 보관하세요.
파일 수정 시각이나 크기가 달라지면 텍스처를 다시 읽습니다. 두 값이 모두 동일하게 유지되는
외부 변경은 캐시에서 빠지거나 에디터를 재실행할 때 반영됩니다.

## 렌더링과 실행

브리지 ABI 버전은 2이며 `pe_*` C 함수만 Python 어댑터에서 호출합니다. 화면은 RGB565로
그린 뒤 RGB24로 변환해 Tk에 표시합니다. 단색 면도 실제 2D 스프라이트 경로를 사용합니다.
이미지 알파와 오브젝트 불투명도를 함께 적용하며 레이어가 같으면 목록 순서대로 그립니다.
회전은 좌상단 기준 시계 방향입니다. 음수 X/Y 배율은 뒤집기로 사용합니다.

실행 시 프로젝트를 깊게 복제합니다. `motion2d.velocity`는 초당 픽셀입니다. 충돌이 없는 기존
오브젝트는 `controlled: true`이면 키 입력 방향에 `speed`를 추가하며 대각선 속도를 정규화합니다.
충돌을 켠 이동 물체는 초기 속도 이후 중력·접촉 상태를 유지하고, 조작 시 가로 속도를 입력으로
정합니다. 고정 물체는 조작·자동 이동으로 움직이지 않습니다. 충돌·트리거·점프의 세부 계약은
[collision2d.md](collision2d.md)를 참고하세요.
시뮬레이션은 60Hz, 화면 갱신은 최대 약 30Hz이며 지연 프레임의 보충 연산은 최대 5회입니다.
키 입력은 게임 캔버스에 포커스가 있을 때 받으며 포커스를 잃으면 눌림 상태를 지웁니다.
정지는 실행 복제본을 버리며, 실행 중 저장은 편집 프로젝트를 저장합니다.

현재 모델은 검증된 미지의 컴포넌트와 3D 축도 보존합니다. 2D 어댑터는 보이는 다른 종류의
오브젝트를 조용히 누락하지 않고 오류로 거부합니다. 3D 확장 시 해당 어댑터를 추가해야 합니다.

## 현재 범위

- 2D 스프라이트/색 면 배치, 속성 편집, 이미지, 선택·복제·삭제, 실행 취소/다시 실행.
- 편집 화면 확대·축소·이동, 실행·일시정지·정지, 키보드/자동 이동.
- 프로젝트 최대 512오브젝트. 해상도 각 축 최대 2048, 전체 최대 1,048,576픽셀.
- 프로젝트 JSON 최대 4MiB. 이미지 파일 최대 32MiB, 디코딩 크기 각 축 최대 4096.
- 텍스처 캐시는 최대 64항목/64MiB이며 최근 사용하지 않은 항목을 해제합니다.
- 렌더링은 RGB565입니다. 고해상도·여러 큰 이미지에서는 PC CPU와 이미지 변환 비용이 증가합니다.
- 충돌 영역·고정/이동 물체·트리거·중력·점프 설정과 편집/실행 중 충돌 영역 표시.
- 게임 EXE 내보내기, 범용 강체 물리, 스크립트·타임라인·3D 편집은 후속 작업입니다.

실행 명령은 [에디터 README](../tools/editor/README.md)에 있습니다.
