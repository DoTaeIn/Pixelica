## 1. 구성 요소 한눈에 보기

| 컴포넌트 | CMake 타깃 | 공개 헤더 | 하는 일 | 3D 코드 |
|---|---|---|---|---|
| common | `Pixelica::common` | `status.h` `input.h` `platform.h` `math.h` `animation.h` `image.h` `assets_common.h` | 수학, 입력, 애니메이션, 컨테이너/텍스처 에셋 | 없음 |
| renderer2d | `Pixelica::renderer2d` = `Pixelica2D::core` | `renderer2d.h` | 2D 소프트웨어 렌더러 | 없음 |
| renderer3d (core) | `Pixelica::core` = `Pixelica::renderer3d` | `pixelica.h` `renderer.h` `assets.h` `scene.h` | 기존 3D 렌더러 | 3D |
| hybrid | `Pixelica::hybrid` | `hybrid.h` | 3D 깊이 버퍼 위에 2D 빌보드/HUD | 3D+2D 둘 다 필요 |
| skeleton, ik | `Pixelica::skeleton`, `Pixelica::ik` | `skeleton.h`, `ik.h` | 선택 모듈(기본 OFF), 수학만 사용 | 없음 |

2D 전용 SDK에는 3D 렌더러·컨텍스트·씬·메시/카트 코드와 3D 헤더(`pixelica.h`, `renderer.h`, `assets.h`, `scene.h`)가 **들어 있지 않습니다**.
2D 코드는 `#include "pixelica/renderer2d.h"` 하나로 시작합니다(공용 헤더를 포함해 `PIXELICA_Texture`, `PIXELICA_RGB565`, `PIXELICA_Vec2`, 애니메이션을 제공).

## 2. 기본 플래그와 빌드 프로파일

| 옵션 | 기본값 | 의미 |
|---|---|---|
| `PIXELICA_BUILD_3D` | `ON` | 3D 렌더러(`pixelica_core`). OFF면 3D 코드는 빌드·설치되지 않음 |
| `PIXELICA_BUILD_2D` | 최상위 `ON`, 하위 프로젝트(add_subdirectory) `OFF` | 2D 렌더러 |
| (hybrid) | 2D와 3D가 둘 다 켜졌을 때만 | 별도 옵션 없음. 하나라도 꺼지면 빌드되지 않음 |
| `PIXELICA_BUILD_SKELETON`, `PIXELICA_BUILD_IK` | `OFF` | 선택 모듈 |
| `PIXELICA_PLATFORM` | 최상위 `SDL3`, 하위 `HEADLESS` | `SDL3` 또는 `HEADLESS` |
| `PIXELICA_BUILD_EXAMPLES`, `PIXELICA_BUILD_TESTS` | 최상위 `ON` | 예제/테스트 |

```text
조각(fragment): 소스 트리에서 프로파일 구성
cmake -S . -B build-both   -DPIXELICA_PLATFORM=HEADLESS                                  # 3D + 2D + hybrid (기본)
cmake -S . -B build-3d     -DPIXELICA_PLATFORM=HEADLESS -DPIXELICA_BUILD_2D=OFF                # 기존과 같은 3D 전용
cmake -S . -B build-2d     -DPIXELICA_PLATFORM=HEADLESS -DPIXELICA_BUILD_3D=OFF                # 2D 전용: 3D 오브젝트 코드 없음
cmake -S . -B build-common -DPIXELICA_PLATFORM=HEADLESS -DPIXELICA_BUILD_3D=OFF -DPIXELICA_BUILD_2D=OFF  # 공용만
```

데모 실행 파일: `hello_2d`, `hello_isometric`(2D가 켜졌을 때), `hello_25d`(2D와 3D가 모두 켜졌을 때). 3D 예제와 `pixel_room`은 3D가 켜졌을 때만 있습니다.
테스트: `test_renderer2d`는 2D 켜짐, `test_hybrid`는 둘 다 켜짐, 공용 수학/입력/애니메이션 테스트는 3D가 꺼져도 등록됩니다.

## 3. API 소유권 규칙

모든 2D 호출은 **호출자 소유 메모리**만 다룹니다. 렌더러는 할당하지 않고, 전역 가변 상태가 없고, 숨은 그리기 큐가 없습니다.

| 대상 | 소유자 | 규칙 |
|---|---|---|
| 색 버퍼 `PIXELICA2D_Surface::pixels` | 호출자 | RGB565, 행 0이 위. `stride >= width`, 영역 크기 `(height-1)*stride + width`. 패딩 영역은 건드리지 않음 |
| 깊이 버퍼 `depth` | 호출자(선택) | `uint16_t`, `depth_stride >= width`. 색 버퍼와 겹치면 안 됨. 깊이 테스트/쓰기를 쓰려면 필요 |
| `PIXELICA2D_Context` | 호출자 | `pixelica2d_init`이 표면을 **값으로 복사**. 표면의 포인터 대상은 컨텍스트가 쓰는 동안 유효해야 함. `init`은 지우지 않음 |
| 텍스처 `PIXELICA_Texture::pixels` | 호출자 | 그리는 호출 동안만 읽음. 목적지 색/깊이와 겹치면 거부 |
| 타일맵 `tiles` | 호출자 | 호출 동안만 읽음. 비어 있지 않은 모든 ID를 화면 밖 타일까지 먼저 검증 |
| `PIXELICA2D_Item` 목록, `order` 작업공간 | 호출자 | `order_count >= count`, 너무 작으면 `PIXELICA_ERR_NO_MEMORY`. 서로·표면·컨텍스트와 겹치면 안 됨. 포인터는 호출 동안만 사용 |
| 폰트 `rows` | 호출자 | 글리프마다 1바이트 행(bit7이 왼쪽), 글리프 우선 배열 |
| 통계 `PIXELICA2D_Stats` | 컨텍스트 | 수락된 그리기 수와 쓴 픽셀 수, `UINT32_MAX`에서 포화. `pixelica2d_clear`가 초기화 |
| hybrid 뷰 | **3D 컨텍스트가 소유**, 2D는 빌림 | `pixelica2d_bind_3d` 결과는 `pixelica_end_frame`/`pixelica_destroy`/다음 `pixelica_begin_frame` 뒤 사용 금지. 보관하지 말고 프레임마다 다시 bind. 출력 `PIXELICA2D_Context`는 3D 엔진 할당 전체(컨텍스트, 색/깊이 버퍼, 아레나, 가드)와 겹치면 안 되며, 겹치면 아무것도 쓰지 않고 거부 |

검증 규칙: 잘못된 인자(NULL, 범위 밖, 비유한 float, 겹침, 작업공간 부족)는 `PIXELICA_ERR_INVALID_ARG` 또는 `PIXELICA_ERR_NO_MEMORY`를 돌려주고
**픽셀·깊이·통계를 바꾸지 않습니다**. 목록·타일맵·텍스트는 전체를 먼저 검증한 뒤 첫 픽셀을 씁니다. 반환 상태를 무시하지 마세요 —
데모는 모든 호출의 상태를 위로 전파합니다.

스레딩: 컨텍스트와 표면은 한 스레드에서만 사용합니다. 서로 다른 컨텍스트/표면은 상태를 공유하지 않습니다.

## 4. 좌표계: 2D 화면은 Y 아래, 3D 월드는 Y 위

| | 2D (renderer2d) | 3D (renderer3d) |
|---|---|---|
| +X | 오른쪽 | 오른쪽 |
| +Y | **아래** | **위** |
| 카메라 | 2D 카메라: `(월드 - camera.position) * zoom` | 카메라는 -Z를 봄(오른손 좌표계) |
| 회전 | 양의 라디안 = 화면에서 **시계 방향** | 오른손 규칙 (`math.h`) |
| 픽셀 | 행 0 = 위, 픽셀 중심 샘플 | NDC y 위 → 화면 y 아래로 뒤집힘 |

- 2D 스프라이트의 `position`은 월드 좌표이고 `pivot`은 **소스 사각형 안의 텍셀 좌표**(사각형 밖도 가능)입니다. 음수 스케일은 뒤집기입니다.
  스케일은 0이 아니어야 하고 유한해야 합니다.
- HUD용 `pixelica2d_fill_rect`, `pixelica2d_draw_text`는 **화면 좌표**를 쓰고 카메라와 깊이를 무시합니다.
- 하이브리드에서 3D 점은 `pixelica25d_project`가 화면 픽셀(+Y 아래)로 바꿉니다. 빌보드의 위치 인자만 3D(+Y 위)이고 나머지 스프라이트 속성은 2D입니다.
  빌보드 외형의 `scale.x/y`는 **부호만** 뒤집기 방향으로 쓰입니다([7장](#7-hud와-3d-깊이-알파쓰기-정책-hybrid)).
- 픽셀 정확한 결과를 원하면 스프라이트 위치를 정수 픽셀로 반올림하세요(데모가 그렇게 합니다). 소스 샘플링은 항상 가장 가까운 텍셀입니다.

## 5. 그리기 규칙 요약

- **컬러키**: `color_key_enabled`이면 RGB565 값이 정확히 같은 텍셀을 버립니다(버려진 텍셀은 색도 깊이도 쓰지 않음).
- **불투명도**: 0이면 아무것도 쓰지 않음(깊이 포함), 255면 정확히 원본. 그 사이는 5/6비트 채널별 `(src*a + dst*(255-a) + 127)/255`.
- **깊이**: `depth_test`는 엄격한 `<`(같으면 기존 유지), `depth_write`는 셰이딩 뒤 선택적 기록. 둘 중 하나라도 켜면 깊이 버퍼가 필요.
  유효 깊이는 0..65534이고 65535는 "비어 있음"(`PIXELICA2D_DEPTH_CLEAR`)입니다.
- **클립**: `pixelica2d_set_clip`은 표면과 교집합. 0 크기는 허용(아무것도 그리지 않음), 음수 크기는 오류. `NULL`은 전체로 되돌림.
- **통계**: 수락된 그리기마다 `draw_calls` 1(완전히 잘리거나 투명해도 수락이면 1). `pixels_written`은 실제로 쓴 픽셀.
- **`pixelica2d_sprite_frame`**: 규칙적인 격자 아틀라스에서 프레임 선택(셀 크기가 아틀라스를 나눠야 함). 소스 사각형만 바꾸고 실패 시 불변.
- **타일맵**: 타일 ID는 아틀라스 격자의 행 우선 인덱스, `UINT16_MAX`는 빈 칸. `stride_tiles >= cols`, 칸 수 ≤ 1048576. 보이는 칸만 그립니다.
- **텍스트**: 바이트 단위(UTF-8 셰이핑 없음), `\n`은 줄바꿈(`높이 + 1`), 폰트 범위 밖 바이트는 잉크 없이 `너비 + 1`만 진행.
  데모 폰트(`demo_art_font`)는 대문자·숫자·일부 기호(ASCII 32..90)만 있습니다.
- **그리기 목록**(`pixelica2d_draw_list`): `layer` 오름차순 → `sort_y` 오름차순 → 입력 순서(안정). 모든 `sort_y`는 유한해야 함.
  항목 수 ≤ 65536, 삽입 정렬 O(n²).

## 6. 아이소메트릭: 높이와 페인터 순서

### 6.1 투영 (`PIXELICA2D_Iso`)

월드 `(x, y)`는 바닥(타일 단위), `z`는 높이(픽셀 단위, `height_scale`로 조절)입니다.

```text
screen.x = origin.x + (x - y) * tile_width  / 2
screen.y = origin.y + (x + y) * tile_height / 2 - z * height_scale
```

`pixelica2d_iso_unproject`는 **알려진 높이**에서 역변환합니다(`z`는 화면만으로는 결정되지 않기 때문). 타일 크기와 `height_scale`은 유한하고,
너비·높이는 양수, `height_scale >= 0`이며, 결과가 float 범위를 넘으면 실패하고 출력은 바뀌지 않습니다. 화면에서 +x는 오른쪽 아래, +y는 왼쪽 아래입니다.

`hello_isometric`은 32x16 다이아몬드 타일을 쓰므로 타일 `(i, j)`의 위쪽 꼭짓점이 `project(i, j, 0)`이고, 스프라이트 피벗을 `(16, 0)`에 둡니다.

### 6.2 페인터 순서와 `ground_y`

깊이 버퍼가 없으니 가림은 **그리는 순서**로만 만듭니다. 뒤에 있는 것을 먼저 그립니다.

- 정렬 키(`sort_y`)는 객체가 **지면에 닿는 점의 화면 y**(높이 0일 때의 y)입니다. 점프로 `z`가 올라가도 키는 바뀌지 않으므로 점프하는 캐릭터가
  옆 상자 앞뒤로 튀지 않습니다.
- `layer`로 큰 단위를 나눕니다: 바닥 0, 그림자 1, 상자·캐릭터 2.
- 같은 키는 입력 순서가 결정합니다(안정). 쌓은 상자는 아래 상자를 먼저 넣어 위 상자가 나중에 그려지게 합니다.
- 1x1 칸을 차지하는 상자는 그 칸 **중심**의 지면 y를 키로 쓰면 앞/뒤 판정이 맞습니다.
- 한계: 서로 걸치는 큰 객체의 완전한 위상 정렬은 하지 않습니다(계획서 5·6장).

## 7. HUD와 3D 깊이, 알파·쓰기 정책 (hybrid)

| 그리는 것 | 깊이 테스트 | 깊이 쓰기 | 비고 |
|---|---|---|---|
| 3D 메시 | 예 | 예 | 3D 렌더러 |
| 빌보드(불투명, 컬러키) | **항상 예**(강제) | 외형의 `depth_write`(보통 true) | 투명 텍셀(키·불투명도 0)은 색도 깊이도 쓰지 않음 |
| 빌보드(반투명) | 항상 예 | 보통 **false** 권장 | 반투명이 깊이를 쓰면 뒤의 것이 구멍처럼 사라짐 |
| HUD (`fill_rect`, `draw_text`) | 무시 | 쓰지 않음 | 화면 좌표, 카메라 무시. 3D 위에 그대로 덮임 |

빌보드 호출 규칙(`pixelica25d_draw_billboard`):

- 외형(`PIXELICA2D_Sprite`)에서 읽는 것: 텍스처, 소스 사각형, 피벗, 회전, 불투명도, 컬러키, `depth_write`, 그리고 `scale.x/y`의 **부호**.
  덮어쓰는 것: 위치(투영된 화면점), 깊이(투영 값), `depth_test = true`, 스케일의 **크기**(`world_size`·`pixels_per_unit`/소스 크기로 계산).
- **좌우/상하 뒤집기.** 외형의 `scale.x` 또는 `scale.y`를 음수로 두면 해당 축으로 미러링됩니다(별도 시트가 필요 없음). 두 값은 유한하고 0이 아니어야
  하며, 크기는 부호와 무관하게 `world_size`가 정합니다(`scale = ±1`이면 충분). 위치·깊이·`depth_test`는 계속 덮어쓰이므로 외형의 값은 무시됩니다.
- `world_size`는 유한한 양수여야 합니다(뒤집기는 `world_size`가 아니라 외형 스케일의 부호로 지정).
- **앵커.** 피벗이 투영된 점에 놓입니다. 발 위치를 월드 점으로 쓰면 피벗은 `(너비/2, 높이)`, 몸 중앙을 쓰면 `(너비/2, 높이/2)`입니다.
  단일 깊이이므로 위에서 내려다보는 카메라에서는 몸 중앙 앵커가 가림이 가장 자연스럽습니다(`hello_25d`).
- 깊이 버퍼가 없는 캔버스는 거부됩니다. 오류가 있으면(외형 포함) 점이 카메라 뒤여도 `PIXELICA_ERR_INVALID_ARG`입니다.
- 카메라 뒤·근평면 앞·원평면 너머는 `PIXELICA_OK`이지만 아무것도 그리지 않고 통계도 늘지 않습니다. 앵커가 화면 밖이어도 큰 스프라이트는 걸쳐 그려집니다.
- 2D 카메라는 무시되고 보존됩니다(스크롤 카메라가 빌보드를 움직이지 않음). 클립은 적용됩니다.
- **통계는 분리됩니다**: 메시는 `pixelica_frame_stats(ctx)`(3D), 빌보드·HUD는 `canvas.stats`(2D)에만 집계됩니다.
- `pixelica25d_project`: 클립 변환을 double로 계산하고 깊이를 `round((ndc_z+1)/2 * 65534)`로 구합니다(65535는 절대 나오지 않음).
  `pixels_per_unit_x/y`는 행렬 첫 두 행 길이로 구하며 **표준 대칭 원근/직교 + 직교 정규 카메라**에서만 의미가 있습니다.
- **깊이 동률.** 메시와 빌보드는 같은 명목 0..65534 양자화 규칙을 쓰지만, 메시는 float, 빌보드 투영은 double로 계산하므로 경계에서 반올림이 달라질 수 있습니다
  (대개 1단위). 같은 평면에 놓인 메시와 빌보드가 정확히 같은 깊이가 되리라고 가정하지 마세요. 엄격한 `<` 규칙에서는 동률일 때만 먼저 그린 쪽이 남으므로,
  같은 평면에서 겹치게 두지 말고 깊이 값이 분명히 달라지도록 간격을 두세요.
- **단일 깊이 한계.** 빌보드 전체가 투영된 한 점의 깊이 하나를 가집니다(위 앵커 설명). 세로로 긴 스프라이트가 비스듬히 선 3D 면과 교차하는 경우를 정확히 처리하지 않습니다.
- **투영 한계.** 화면 크기 환산(`pixels_per_unit`)은 표준 대칭 원근/직교 투영 + 직교 정규 카메라에서만 약속됩니다. 비스듬한(oblique)·전단·비균일 스케일 카메라에서는
  빌보드 크기를 약속하지 않습니다.

## 8. 공용 에셋과 애니메이션

- 스프라이트 시트는 평범한 RGB565 배열 + 컬러키입니다. `PIXELICA_Texture{pixels, width, height}`는 2D와 3D가 공유하며(`pixelica/image.h`), 배열만으로 2D SDK에서
  바로 쓸 수 있습니다. 새 포맷은 없습니다.
- `.p3tex`가 필요하면 저장소의 `tools/pixelica_pack/pixelica_pack.py texture`로 만들고 공용 `pixelica_texture_asset_*`(`pixelica/assets_common.h`)로 읽습니다. 이 변환 도구는
  **2D SDK ZIP에 들어 있지 않습니다**(3D SDK ZIP의 `share/Pixelica/tools/pixelica_pack/`에는 있음). 2D SDK만 쓰는 경우 저장소 체크아웃에서 도구를 실행해 만든 `.p3tex`를
  프로젝트 에셋으로 가져가세요.
- 데모의 아트(`examples/common2d/demo_art.h`)는 C 배열(ASCII 아트 → 팔레트 → RGB565)과 간단한 수식으로 생성됩니다. 생성기는 용량과 문자열 길이를
  먼저 검사하고, 캐릭터는 16x24 4프레임 걷기 사이클입니다.
- **애니메이션**은 공용 모듈을 그대로 씁니다: `PIXELICA_AnimPlayer`(틱 커서) + `PIXELICA_AnimKeyframe` 트랙 + `pixelica_anim_sample`이 실수 값을 주고,
  걷기 프레임은 `STEP` 이징 키로, 점프 높이는 `QUAD_OUT/QUAD_IN` 키로 만듭니다. 그 값을 `pixelica2d_sprite_frame`의 프레임 번호나 아이소 `z`에 넣습니다.

## 9. 독립 2D/3D SDK ZIP과 2.5D 합치기

`tools/package_sdk.py`(Python 표준 라이브러리만 사용)가 한 번의 빌드에서 ZIP 두 개를 만듭니다. 두 ZIP 모두 최상위 디렉터리가 `Pixelica-0.1.0/`이고,
파일 이름은 `Pixelica2D-0.1.0-<플랫폼 태그>.zip`, `Pixelica3D-0.1.0-<플랫폼 태그>.zip`입니다. 기본 플랫폼 태그는 실행한 머신의 `<OS>-<아키텍처>`입니다.

| ZIP | 설치 컴포넌트 | 들어 있는 것 | 들어 있지 않은 것 |
|---|---|---|---|
| Pixelica2D | `common` + `renderer2d` | 공용 헤더, `renderer2d.h`, 공용/2D 정적 라이브러리(Debug + Release), `Pixelica2D`/`Pixelica` 패키지 설정, `share/Pixelica/template2d`, 문서 | 3D 헤더, `pixelica_core`, hybrid, `pixelica_pack` 에셋 도구, 3D 템플릿 |
| Pixelica3D | `core` + `hybrid` | 3D 헤더와 `hybrid.h`, 3D/hybrid 정적 라이브러리(Debug + Release), 패키지 설정, `share/Pixelica/template`, `share/Pixelica/tools/pixelica_pack`, 문서 | 2D 렌더러(`renderer2d.h`, `Pixelica2D` 설정) |

두 ZIP 어디에도 SDL은 들어 있지 않습니다(헤드리스 빌드이며 화면 출력은 사용자가 `PIXELICA_PlatformOps`로 제공). 선택 모듈 skeleton / IK는 기본 OFF이고 두 ZIP에
포함되지 않습니다. 필요하면 [`rigging.md`](rigging.md)대로 독립적으로 빌드·설치합니다. 각 ZIP에는 `share/doc/<이름>/MANIFEST.json`(경로·크기·SHA256)이 있고,
출력 디렉터리에는 `SHA256SUMS.txt`가 함께 쓰입니다.

```text
조각(fragment): 패키징 (저장소 루트에서, Python 3과 CMake 3.21+ 필요)
python tools/package_sdk.py --build-dir build-sdk --output-dir dist
python tools/package_sdk.py --generator "Visual Studio 17 2022" --platform x64 --build-dir build-sdk --output-dir dist --jobs 8
python tools/package_sdk.py --cmake <cmake 경로> --build-dir <빌드 디렉터리> --output-dir <출력 디렉터리> --dry-run   # 계획만 출력, 아무것도 실행/생성하지 않음
```

- `--platform`은 CMake 생성기 플랫폼(`-A`, 예: `x64`)이며 ZIP 이름의 태그가 아닙니다. `--build-dir` 기본값은 `<소스>/build-sdk`, `--output-dir` 기본값은 `<빌드 디렉터리>/archives`입니다.
  스크립트는 아무것도 삭제하지 않고 기존 ZIP도 덮어쓰지 않습니다(이미 있으면 오류).
- 두 ZIP은 **같은 버전(0.1.0)의 별도 설치**입니다. 아무 위치에나 풀 수 있고(패키지 설정은 재배치 가능, 절대 경로 없음) `CMAKE_PREFIX_PATH`에 그 위치를 주면 됩니다.
  `Pixelica2DConfig.cmake`는 같은 prefix의 `Pixelica` 설정을 옆에서 찾습니다(관련 없는 전역 설치를 찾지 않음).
- **2D만**: 2D ZIP만 풀고 `find_package(Pixelica2D CONFIG REQUIRED)` → `Pixelica2D::core`. 시작점은 `share/Pixelica/template2d`(저장소의 [`sdk/template2d`](../sdk/template2d/README.md))입니다.
- **3D만**: 3D ZIP만 풀고 `find_package(Pixelica CONFIG REQUIRED)` → `Pixelica::core`(옛 사용법 그대로).
- **2.5D**: 두 ZIP을 **같은 빈 디렉터리**에 풉니다. 공용 파일(패키지 설정, 공용 헤더·라이브러리)이 양쪽에 있어 겹칩니다. 패키지 설정은 "export 파일이 존재하는지"로
  어떤 컴포넌트가 있는지 판단하므로 병합 뒤 `hybrid`가 열립니다.
- **병합이 성립하는 조건.** 정적 라이브러리이므로 두 ZIP이 **같은 버전, 같은 컴파일러, 같은 아키텍처, 같은 구성(Debug/Release) ABI**일 때만 병합을 지원합니다.
  `package_sdk.py`로 한 번에 만든 두 ZIP은 겹치는 공용 파일이 바이트 단위로 같고, 스크립트가 ZIP을 쓰기 전에 이를 검사합니다. 서로 다른 빌드나 컴파일러에서 나온 ZIP을
  섞는 것은 지원하지 않습니다. 의심되면 겹치는 파일의 SHA256을 `MANIFEST.json`으로 비교하세요.
- hybrid는 2D와 3D가 모두 필요하므로 한쪽만 있으면 `COMPONENTS hybrid`가 실패합니다. 선택(OPTIONAL) 컴포넌트가 없을 때는 성공하되 `_FOUND`가 거짓입니다.
- ZIP의 실제 구성·재배치·병합 결과와 해시는 `DIMENSIONS_AUDIT.md` (local-only record)가 기록합니다.

## 10. 완전한 최소 2D 예제

`minimal2d.c`는 3D 헤더 없이 2D 렌더러만 씁니다. 스프라이트 컷·뒤집기·컬러키·클립·카메라·HUD 불투명도·아이소 투영을 그려 **픽셀로 검사**하고, 이상이 없으면
`minimal-2d: OK`를 출력하고 종료 코드 0을 돌려줍니다. (PAL present는 실제 프로그램에서 `ops.present_rgb565(...)`를 프레임당 한 번 호출합니다.)

```c
#include <stdbool.h>
#include <stdint.h>
#include <stdio.h>

#include "pixelica/renderer2d.h"

#define WIDTH 64
#define HEIGHT 48

#define BG PIXELICA_RGB565(0, 0, 64)
#define RED PIXELICA_RGB565(248, 0, 0)
#define GREEN PIXELICA_RGB565(0, 248, 0)
#define KEY PIXELICA_RGB565(248, 0, 248) /* transparent color of the sheet */
#define WHITE PIXELICA_RGB565(248, 252, 248)

static uint16_t g_target[WIDTH * HEIGHT]; /* RGB565 color target, row 0 = top, owned by the caller */
static uint16_t g_sheet[16 * 8];          /* sprite sheet: two 8x8 frames side by side */
static int g_failures;

static uint16_t pixel_at(int x, int y)
{
    return g_target[y * WIDTH + x];
}

static void expect(const char *what, bool ok)
{
    if (!ok) {
        ++g_failures;
        fprintf(stderr, "FAILED: %s\n", what);
    }
}

/* Same arithmetic as the renderer: (src * a + dst * (255 - a) + 127) / 255 per channel. */
static uint16_t blend565(uint16_t src, uint16_t dst, unsigned alpha)
{
    const unsigned r = ((((unsigned)src >> 11) & 31u) * alpha +
                        (((unsigned)dst >> 11) & 31u) * (255u - alpha) + 127u) / 255u;
    const unsigned g = ((((unsigned)src >> 5) & 63u) * alpha +
                        (((unsigned)dst >> 5) & 63u) * (255u - alpha) + 127u) / 255u;
    const unsigned b = (((unsigned)src & 31u) * alpha +
                        ((unsigned)dst & 31u) * (255u - alpha) + 127u) / 255u;
    return (uint16_t)((r << 11) | (g << 5) | b);
}

/* Draws atlas frame `frame` (8x8 cells) with its top-left corner at (x, y); scale_x < 0 mirrors. */
static bool draw_frame(PIXELICA2D_Context *ctx, const PIXELICA_Texture *sheet, uint32_t frame, float x,
                       float y, float scale_x)
{
    PIXELICA2D_Sprite sprite;

    if (pixelica2d_sprite_init(&sprite, sheet) != PIXELICA_OK ||
        pixelica2d_sprite_frame(&sprite, frame, 8, 8) != PIXELICA_OK) {
        return false;
    }
    sprite.position.x = x;
    sprite.position.y = y;
    sprite.scale.x = scale_x;
    sprite.color_key_enabled = true;
    sprite.color_key = KEY;
    return pixelica2d_draw_sprite(ctx, &sprite) == PIXELICA_OK;
}

int main(void)
{
    PIXELICA2D_Surface surface;
    PIXELICA2D_Context ctx;
    PIXELICA_Texture sheet;
    PIXELICA2D_Camera camera = {{5.0f, 0.0f}, 1.0f};
    PIXELICA2D_Rect clip = {0, 0, 32, 48};
    PIXELICA2D_Rect bar = {0, 0, 64, 4};
    PIXELICA2D_Rect hidden = {0, 4, 64, 4};
    PIXELICA2D_Rect glass = {0, 8, 8, 2};
    PIXELICA2D_Iso iso = {32.0f, 16.0f, 1.0f, {32.0f, 8.0f}};
    PIXELICA_Vec3 cell = {1.0f, 0.0f, 0.0f};
    PIXELICA_Vec2 screen;
    PIXELICA_Vec2 back;
    int x;
    int y;

    /* Art: frame 0 is red with a keyed top-left texel, frame 1 is green with a keyed top-right texel. */
    for (y = 0; y < 8; ++y) {
        for (x = 0; x < 16; ++x) {
            g_sheet[y * 16 + x] = (uint16_t)(x < 8 ? RED : GREEN);
        }
    }
    g_sheet[0] = KEY;
    g_sheet[8 + 7] = KEY;
    sheet.pixels = g_sheet;
    sheet.width = 16;
    sheet.height = 8;

    surface.pixels = g_target;
    surface.width = WIDTH;
    surface.height = HEIGHT;
    surface.stride = WIDTH;
    surface.depth = NULL; /* no depth buffer needed for plain 2D */
    surface.depth_stride = 0;
    if (pixelica2d_init(&ctx, &surface) != PIXELICA_OK || pixelica2d_clear(&ctx, BG) != PIXELICA_OK) {
        return 1;
    }

    /* Plain draw: the keyed corner shows the background. */
    if (!draw_frame(&ctx, &sheet, 0, 10.0f, 10.0f, 1.0f)) {
        return 1;
    }
    expect("keyed texel is transparent", pixel_at(10, 10) == BG);
    expect("opaque texels are drawn", pixel_at(11, 10) == RED && pixel_at(10, 11) == RED &&
                                         pixel_at(17, 17) == RED);
    expect("nothing outside the sprite", pixel_at(18, 10) == BG && pixel_at(9, 10) == BG);

    /* Negative scale mirrors around the position: covers x 32..39, keyed texel ends up at x = 39. */
    if (!draw_frame(&ctx, &sheet, 0, 40.0f, 10.0f, -1.0f)) {
        return 1;
    }
    expect("mirrored keyed texel", pixel_at(39, 10) == BG);
    expect("mirrored body", pixel_at(38, 10) == RED && pixel_at(32, 10) == RED);
    expect("mirrored outside", pixel_at(31, 10) == BG);

    /* Second atlas frame. */
    if (!draw_frame(&ctx, &sheet, 1, 10.0f, 30.0f, 1.0f)) {
        return 1;
    }
    expect("frame 1 is green", pixel_at(10, 30) == GREEN && pixel_at(17, 31) == GREEN);
    expect("frame 1 keyed corner", pixel_at(17, 30) == BG);

    /* Clip: only x < 32 may change. */
    if (pixelica2d_set_clip(&ctx, &clip) != PIXELICA_OK || !draw_frame(&ctx, &sheet, 0, 28.0f, 30.0f, 1.0f) ||
        pixelica2d_set_clip(&ctx, NULL) != PIXELICA_OK) {
        return 1;
    }
    expect("clip keeps inside pixels", pixel_at(31, 32) == RED);
    expect("clip blocks outside pixels", pixel_at(32, 32) == BG);

    /* Camera: world x 20 is screen x 15. */
    if (pixelica2d_set_camera(&ctx, &camera) != PIXELICA_OK || !draw_frame(&ctx, &sheet, 1, 20.0f, 38.0f, 1.0f) ||
        pixelica2d_set_camera(&ctx, NULL) != PIXELICA_OK) {
        return 1;
    }
    expect("camera shifts the sprite", pixel_at(15, 38) == GREEN && pixel_at(22, 39) == GREEN);
    expect("camera keyed corner", pixel_at(22, 38) == BG);

    /* HUD rectangles use screen coordinates; opacity 0 draws nothing, 128 blends. */
    if (pixelica2d_fill_rect(&ctx, &bar, WHITE, 255) != PIXELICA_OK ||
        pixelica2d_fill_rect(&ctx, &hidden, WHITE, 0) != PIXELICA_OK ||
        pixelica2d_fill_rect(&ctx, &glass, WHITE, 128) != PIXELICA_OK) {
        return 1;
    }
    expect("opaque bar", pixel_at(0, 0) == WHITE && pixel_at(63, 3) == WHITE);
    expect("opacity 0 writes nothing", pixel_at(0, 4) == BG);
    expect("half opacity blends", pixel_at(0, 8) == blend565(WHITE, BG, 128) && pixel_at(8, 8) == BG);

    /* Isometric projection: tile (1, 0) at height 0 -> (48, 16); the inverse returns (1, 0). */
    if (pixelica2d_iso_project(&iso, cell, &screen) != PIXELICA_OK ||
        pixelica2d_iso_unproject(&iso, screen, 0.0f, &back) != PIXELICA_OK) {
        return 1;
    }
    expect("iso projection", screen.x > 47.99f && screen.x < 48.01f && screen.y > 15.99f &&
                                 screen.y < 16.01f);
    expect("iso inverse", back.x > 0.99f && back.x < 1.01f && back.y > -0.01f && back.y < 0.01f);

    printf("minimal-2d: %s (draw_calls=%u pixels_written=%u)\n", g_failures == 0 ? "OK" : "FAILED",
           (unsigned)ctx.stats.draw_calls, (unsigned)ctx.stats.pixels_written);
    return g_failures == 0 ? 0 : 1;
}
```

기대 출력의 첫 부분은 `minimal-2d: OK`입니다(괄호 안 통계 값은 구현의 집계 방식에 따라 달라질 수 있으므로 비교 대상이 아닙니다).
이 예제를 컴파일해 실행한 결과는 이 문서가 아니라 `DIMENSIONS_AUDIT.md` (local-only record)를 보세요.

```cmake
cmake_minimum_required(VERSION 3.21)
project(Minimal2D LANGUAGES C)
set(CMAKE_C_STANDARD 11)
set(CMAKE_C_STANDARD_REQUIRED ON)

find_package(Pixelica2D 0.1 CONFIG REQUIRED)   # 2D SDK: Pixelica2D::core, 3D 없음
add_executable(minimal2d minimal2d.c)
target_link_libraries(minimal2d PRIVATE Pixelica2D::core)
```

```text
조각(fragment): 구성과 실행
cmake -S . -B build -DCMAKE_PREFIX_PATH=<2D SDK를 푼 디렉터리> -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release
./build/minimal2d                 # Windows(Visual Studio): build\Release\minimal2d.exe
```

## 11. CMake: Pixelica2D와 hybrid

```text
조각(fragment): 2D 전용 (독립 2D SDK)
find_package(Pixelica2D 0.1 CONFIG REQUIRED)
target_link_libraries(my_game PRIVATE Pixelica2D::core)

조각(fragment): 같은 일을 Pixelica 패키지로 (컴포넌트 지정)
find_package(Pixelica 0.1 CONFIG REQUIRED COMPONENTS renderer2d)
target_link_libraries(my_game PRIVATE Pixelica::renderer2d)

조각(fragment): 2.5D (3D SDK + 2D SDK를 같은 prefix에 푼 뒤)
find_package(Pixelica 0.1 CONFIG REQUIRED COMPONENTS core renderer2d hybrid)
target_link_libraries(my_game PRIVATE Pixelica::hybrid Pixelica::renderer2d Pixelica::core)
```

- 컴포넌트를 주지 않은 `find_package(Pixelica)`는 설치된 export 파일을 보고 3D(있으면) → 2D → 공용 순으로 기본을 고릅니다. 컴포넌트를 주면 요청한 것만 가져옵니다.
- 모든 라이브러리를 기본으로 가져오지 않습니다. `hybrid`는 `core`와 `renderer2d`가 모두 있어야 합니다.
- 소스 트리에서 `add_subdirectory`로 쓸 때도 같은 별칭이 정의됩니다.

## 13. 시작 템플릿 `sdk/template2d`

2D 프로젝트의 시작점입니다. 2D SDK ZIP에는 `share/Pixelica/template2d`로 들어 있고 저장소에서는 `sdk/template2d`입니다.
독립 프로젝트(`find_package(Pixelica2D CONFIG REQUIRED)`, `Pixelica2D::core`만 링크, 3D 헤더·함수 없음, 절대 경로 없음). 타일맵·키 스프라이트·반투명 HUD를 쓰는
작은 게임과 헤드리스 드라이버(`--frames N`, `--capture PATH`, 프레임당 PAL present 1회)를 포함합니다. 엄격 경고 옵션 `PIXELICA2D_GAME_STRICT_WARNINGS`,
CTest(성공 실행, 결정성, 캡처, 잘못된 인자 거부)가 있습니다. 자세한 내용은 [`sdk/template2d/README.md`](../sdk/template2d/README.md).

## 14. 제공하지 않는 것

물리, 오디오, 에디터, 범용 2D 리깅, 완전한 아이소 위상 정렬, 스프라이트 배칭/GPU 경로, 회전하는 타일맵, 알파 채널 에셋. 이 범위는 이번 구현에서도
바뀌지 않았고, 후보 목록은 `2D_25D_PLAN.md` (local-only record) 6장에 있습니다(구현되지 않음).

## 15. 마이크로컨트롤러에서의 2D

2D 렌더러는 GPU 없이 CPU로 그리는 소프트웨어 렌더러입니다. ESP32-P4용 2D 경로(선택 컴포넌트 `pixelica2d`, `pixelica_renderer2d`)는 **컴파일 대상일 뿐**이며,
컴파일 검증 범위는 `DIMENSIONS_AUDIT.md` (local-only record)를 기준으로 하세요. 물리 보드가 없어 보드에서 2D를 실행한 적이 없고
**프레임 속도·메모리·표시 경로는 측정되지 않았습니다.** 데스크톱 결과를 MCU 성능으로 해석하지 마세요.
