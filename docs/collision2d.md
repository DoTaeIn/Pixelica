# 2D 충돌·중력·점프

`pixelica/collision2d.h`는 렌더러와 독립적인 공통 C API입니다. `Pixelica::common`에 포함되므로
2D 전용 SDK와 3D SDK 모두 사용할 수 있습니다. 메모리를 내부에서 할당하지 않습니다.

## 게임 코드에서 사용

좌표는 X 오른쪽, Y 아래쪽입니다. AABB는 축에 정렬된 사각형이며 min/max는 월드 좌표입니다.
넓이와 높이는 양수여야 합니다. `pixelica_aabb2d_overlaps()`는 내부가 겹칠 때만 참을 반환합니다.
변·꼭짓점이 닿기만 하면 겹침은 아닙니다.

`pixelica_aabb2d_move()`에 이동량과 고정 장애물 배열을 넘기면 X, Y 순서로 이동 가능한 거리를
계산합니다. 벽에 막힌 축은 멈추고 나머지 축으로 미끄러집니다. 이동 구간을 검사하므로 큰
이동량으로 얇은 벽을 넘어가는 것을 방지합니다. 처음부터 장애물 안에 있으면 오류를 반환합니다.

`PIXELICA_Body2D`에는 AABB, 현재 속도, 접촉 방향, 바닥 지지 상태를 보관합니다.
`pixelica_body2d_step()`은 중력·낙하 속도 제한·점프·충돌 이동을 처리합니다.
호출 간 같은 body를 유지하고, 외부 입력으로 가로 속도를 갱신하세요.

```c
#include "pixelica/collision2d.h"

int main(void)
{
    PIXELICA_Body2D player = {
        {{10.0f, 0.0f}, {26.0f, 24.0f}}, {0.0f, 0.0f}, 0u, 0u
    };
    const PIXELICA_AABB2D floor_box = {{0.0f, 100.0f}, {320.0f, 120.0f}};
    /* Fixed 60 Hz: gravity px/s^2, jump and fall speed px/s. */
    for (int tick = 0; tick < 120; ++tick) {
        if (pixelica_body2d_step(&player, 1.0f / 60.0f, 600.0f,
                220.0f, 600.0f, false, &floor_box, 1u) != PIXELICA_OK) return 1;
    }
    if (!player.grounded) return 2;
    if (pixelica_body2d_step(&player, 1.0f / 60.0f, 600.0f,
            220.0f, 600.0f, true, &floor_box, 1u) != PIXELICA_OK) return 3;
    return player.velocity.y < 0.0f ? 0 : 4;
}
```

시간 간격은 0보다 크고 0.25초 이하입니다. 중력·점프 속도는 0..10000,
최대 낙하 속도는 0보다 크고 10000 이하입니다. 입력은 유한한 숫자여야 합니다.
실패하면 body와 출력은 변경하지 않습니다. 입력·출력의 금지된 메모리 겹침도 거부합니다.
점프 요청의 눌림/떼기 처리는 게임 입력 계층에서 하세요. C API는 지지된 상태의 점프 요청을
처리하며, 에디터 실행 계층은 키를 계속 눌러도 착지 때 자동으로 다시 점프하지 않도록 합니다.

## 에디터에서 설정

오브젝트를 선택한 뒤 충돌 설정에서 빠른 설정을 사용합니다.

- **고정 벽/바닥:** 다른 물체를 막으며 중력이나 조작으로 움직이지 않습니다.
- **플레이어:** 이동 물체·중력·점프를 설정하고 기존 조작 속도를 사용합니다.
- **트리거:** 통과 가능한 영역입니다. 다른 충돌 영역과 겹치면 이벤트를 발생시킵니다.
- **충돌 없음:** 기존의 자유 이동 방식으로 돌아갑니다.

스프라이트에 맞추기를 켜면 그림 크기로 충돌 영역을 만듭니다. 끄면 오프셋 X/Y와 폭·높이를
직접 지정할 수 있습니다. 오프셋과 크기는 스프라이트의 로컬 좌표이며 오브젝트 배율·회전을
적용한 네 꼭짓점을 감싸는 월드 AABB가 실제 판정 영역입니다. 회전한 그림과 정확히 일치하는
다각형 충돌은 제공하지 않습니다. 충돌 영역 표시에서 이 범위를 확인할 수 있습니다.

실행 중 A/D 또는 좌우 방향키로 이동하고 Space/W/위쪽 방향키로 점프합니다.
중력이 0이면 상하 이동도 가능합니다. 정지하면 위치·속도·접지·트리거 상태는 버려지고 편집
장면으로 돌아옵니다. 충돌 설정은 저장·열기·실행 취소와 함께 처리됩니다.

처음부터 플레이어가 벽 안에 겹쳐 있으면 실행 오류가 납니다. 편집 화면에서 충돌 영역을
분리해 배치하세요. 경계가 닿는 바닥 배치는 정상입니다.

## 프로젝트 컴포넌트와 이벤트

`collider2d`는 enabled, trigger, fit_sprite, offset[2], size[2]를 저장합니다.
`body2d`는 type(static/dynamic), gravity, jump_speed, max_fall_speed를 저장합니다.
컴포넌트가 없는 기존 프로젝트에 충돌이나 중력을 자동으로 추가하지 않습니다.
숨겨진 그림의 충돌 영역도 enabled이면 활성 상태입니다.

에디터의 `PlaySession`은 다음 상태를 공개합니다.

- `grounded`: 바닥에 지지된 오브젝트 ID 집합.
- `active_triggers`: 현재 겹친 (트리거 ID, 상대 ID) 쌍의 집합.
- `trigger_events`: 이번 tick의 (enter/stay/exit, 트리거 ID, 상대 ID) 목록.

트리거는 판정과 이벤트를 제공합니다. 코인 획득·문 열기·씬 전환 등의 효과는 게임이 정합니다.
서로 트리거인 쌍은 정해진 ID 순서로 한 번 보고합니다.
트리거는 tick 끝의 겹침을 검사합니다. 한 tick 사이에 영역 전체를 통과하면 이벤트가 없을 수 있으므로
빠른 물체에 사용하는 트리거는 충분히 넓게 잡거나 시뮬레이션 시간 간격을 줄이세요.

## 범위

이동 물체와 고정 장애물 사이의 사각형 충돌을 지원합니다. 이동 물체끼리의 밀기·충돌 반응,
경사면, 회전 다각형, 반발·마찰·질량, 움직이는 발판 운반, 한 방향 발판은 포함하지 않습니다.
에디터 시뮬레이션은 고정 60Hz입니다. C API는 호출자가 장애물 배열과 시간 간격을 관리합니다.
대규모 월드에서는 게임의 청크 관리로 가까운 장애물만 전달하세요.
